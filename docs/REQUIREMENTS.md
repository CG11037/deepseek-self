## 1. 项目目标

**一句话**：从 AI 对话记录中，用可验证的方式，看见自己的状态、变化与长期模式。

### 三条成功标准

1. **可验证** — 随机抽查 20 条引据，≥90% 确实支撑它所附着的结论，无张冠李戴、无编造。
2. **被说中** — 第一份完整周期报告读完后，用户能指出至少 1 处"这个说得对，我之前没意识到"。
3. **会回访** — 交付后 4 周内，用户主动打开 ≥3 次。达不到即判定项目方向需要重估。

### 关键定位（不要漂移）

- 不是"AI 算命"，不产出定性人格标签。所有人格/状态输出都是**描述性的时间切片**。
- 不是"又一个情绪打卡 App"。最大优势是**零额外负担**——数据已经存在，工具只读。
- 最强差异化是**引据可验证**。市面同类产品的用户吐槽集中在"它只是在说我想要听的话"（Reddit / LinkedIn 实测反馈）。能点开原文核对，是这个项目的护城河。

| 场景 | 节奏 | 时长 | 语气模式 |
|---|---|---|---|

## 3. 数据来源与隐私边界

### 3.1 当前数据源（已实测）

DeepSeek 官方导出 `conversations.json`，34.4 MB。已复制至项目内 `data/conversations.json`。

> **注意**：`data/` 已被 `.gitignore` 排除，该数据**不会入库**。对话记录属私人数据，默认不进版本库；若确需入库，需显式修改 `.gitignore` 并自行承担泄露风险。

| 指标 | 数值 |
|---|---|
| 对话数 | 917 |
| 用户消息（REQUEST） | 4,774 条，2,276,976 字符 |
| AI 正式回复（RESPONSE） | 4,741 条 |
| 过程数据（需剔除） | 12,349 条：THINK 6,002 / TOOL_OPEN 4,781 / TOOL_SEARCH 1,257 / FILE 152 / SEARCH 146 / TOOL_FIND 11 |
| 时间跨度 | 2025-01-27 → 2026-10-09（18 个有数据月份，61 个有数据周） |
| 平均增量 | 约 3.7 万字/周 |
| 模型分布 | deepseek-reasoner 8,790 / deepseek-chat 893 |

### 3.2 数据结构（实测，务必按此解析）

```
顶层：list
conversation: { id, title, inserted_at, updated_at, mapping }
mapping:      { <node_id>: { id, parent, children[], message } }
message:      { model, inserted_at, fragments[] }
fragment:     { type, content }
              type ∈ REQUEST(用户) | RESPONSE | THINK | SEARCH | FILE
                     | TOOL_SEARCH | TOOL_OPEN | TOOL_FIND
```

**⚠️ 两个必须处理的坑（实测发现）：**

1. **必须去重。** `mapping` 是带分支的树（重新生成会产生分支），同一条用户消息会出现多次——实测中同一段"高中回忆"重复出现 4 次。按 `message.id` 去重，否则五维分值和引据会被重复内容带偏。
2. **只保留 REQUEST 和 RESPONSE。** THINK / TOOL_* 是模型内部过程，不含用户信息，占全部片段的 72%，必须剔除。

### 3.3 数据质量实况（决定了分析策略）

| 指标 | 数值 | 含义 |
|---|---|---|
| 对话轮次分布 | 1 轮 309 / 2 轮 150 / 3–5 轮 231 / 6–10 轮 124 / 10+ 轮 103 | **50% 是"问完就走"的工具性查询** |
| 含内在信号的对话 | 142 / 917 = **15.5%** | 大部分对话不反映内在状态 |
| 高信号消息（≥2 类信号 + 非技术 + >40 字） | **63 条** | 真正的自我暴露很少 |
| 高信号时间分布 | 2026-07: 38 / 2026-08: 16 / 其余 18 个月合计 9 | **85% 集中在最近两个月** |

**由此得出两条硬约束：**

- **信号筛选是必做项，不是优化项。** 若把 917 条全喂给模型打分，测出的是"你这周学 Hadoop 学得很猛"，不是你的焦虑水平。
- **长期分析要分层。**
  - 行为/认知层（关注领域迁移、提问方式演变、活跃时段、对话深度）：**全量 917 条都算得出，可画 20 个月曲线**。
  - 情绪/内在层：历史周期信号稀疏，**必须显式标注"信号不足"，禁止插值、禁止编造**。

### 3.4 隐私边界

| 项 | 决策 |
|---|---|
| 存储 | 纯本地 SQLite，不做云同步 |
| 加密 | **不做**（用户明确决定），保留"可直接用 SQLite 工具打开"的便利性 |
| 红线内容 | 代码、密钥、内网地址、财务数据 → **局部打码**替换为 `[REDACTED]`，消息本身继续参与分析（不整条剔除，会丢太多有效数据） |
| 其余内容 | **不脱敏**（用户判断：这些数据本来就已在 DeepSeek，再送 DeepSeek API 不新增暴露面） |
| 分析模型 | 用户自选厂商、自备 Key。**跨平台数据流动（如用 DeepSeek 分析 ChatGPT 导出）的知情权归用户**，UI 需明示 |
| 分享 | 默认自己看。提供**脱敏开关**，开启后输出二次脱敏的静态快照 |

## 4. 分析维度与优先级

### 4.1 五维状态（顶层仪表盘）

`精力 / 焦虑 / 专注度 / 社交欲 / 创造力`，偏向内在状态。
**每个维度的分值必须配引据**（1–2 条真实对话摘要/原句），无引据的分数不展示。

### 4.2 六个层次

| 层 | 内容 | 成本 | 优先级 |
|---|---|---|---|
| L0 行为层 | 活跃时段、频率、断档、话题分布、对话深度 | 纯统计，零 API | **P0** |
| L1 认知层 ★ | 提问类型（求解/理解/验证/倾诉）、重复提问、放弃点、修正行为、依赖度 | 需 LLM | **P0** |
| L2 情绪层 | 情绪原语 + 触发对象 + 强度 | 需 LLM | **P0** |
| L3 动机层 | 反复出现的目标、未兑现的意图、在乎与回避 | 需 LLM | P1 |
| L4 模式层 ★ | 言行落差、重复困境、长期稳定模式（"从未改变的事"） | 跨周期 | P2 |
| L5 叙事层 | 半年跨度转折、"年初的你 vs 现在的你" | 长周期 | P2 |

★ = 竞争壁垒。L1 是**只有 AI 对话数据才能做的**：日记记录的是结论，AI 对话记录的是思考过程。

### 4.3 输出三层（全都要）

**描述层** → **归因层** → **行动层**。工具既是镜子，也是教练。

### 4.4 人格的处理方式

**分层方案**：人格 = 长期底色（按季度/全量更新，看缓慢漂移，两张图分开呈现）；五维 = 每周波动。
人格不是定性标签，UI 需标注"基于对话文本的推测，非心理测量"。

### 4.5 事件层（首屏主视图）

四类信号，主要靠机械层检测，语义层只负责命名与定性：

- **开始**：话题从无到有
- **结束**：话题消失 —— **必须区分"完成了"与"放弃了"**（靠末尾对话的完成信号判断，如"通关了游戏然后没玩了"）
- **峰值**：消息量突然翻倍（赶工 / 危机 / 沉迷）
- **空档**：整段沉默 —— **显式标注，不插值抹平**。"你消失了三个月"本身就是要看见的事实

转折点 = 相邻周期话题分布的突变超过阈值。

### 4.6 情绪原语

**采用自下而上生成**：先让模型通读全部对话，用**用户自己的语言**归纳出 20–40 个个人情绪词，用户确认/重命名/合并后固化为 profile，后续分析用该词表打分。

- 理由：预设词表会把"怕来不及 / 怕选错 / 怕被看穿"全压成"焦虑"，而这三种对应的行动完全不同。
- 代价与对策：词表不稳定导致跨周期不可比 → **词表版本化**，换版本时对历史周期回溯重算，或仅在新周期启用。
- **情绪必须绑定触发对象**。"焦虑 7 分"无用，"焦虑（面试）7 分"才能导出行动。

### 4.7 实体模型（统一抽象，不要建独立模块）

**兴趣、项目、任务、人、目标、工具、游戏、自我信念 —— 都是"实体"**，共用一张表：

```
entity: { id, name, type, first_seen, last_seen,
          activity_curve[per_period], status: 活跃|休眠|结束|复活,
          emotion_profile, is_task: bool }
```

`type` 由 LLM 判定（兴趣 / 项目 / 任务 / 人物 / 自我信念）。所有上层视图都是这张表的不同切面：

| 视图 | 查询方式 |
|---|---|
| 话题分布 | 按周期聚合全部实体 |
| 兴趣图谱 | 过滤：持续 ≥3 个月 且 非任务型 |
| 事件轨迹 | 实体的开始/结束/峰值事件流 |
| 转折检测 | 相邻周期实体集合的突变 |
| 五维引据 | 反查实体绑定的原话 |

**第三类实体尤其重要：自我信念。** 用户在对话中对自己下的定义（"我这人就是容易拖""我想做独立游戏"）建成实体，追踪其出现、变化与自相矛盾 —— 即"自我叙事的演化"。这是本项目的独特价值。

| 不做 | 原因 |

## 7. 技术约束与依赖

### 7.1 形态（重要）

**第一版 = Python 脚本 + 本地 HTML 报告。Tauri 2 + React 推迟到语义层打磨满意之后。**

理由：Tauri/React 环境搭建与打包会吃掉 1–2 周且不产生任何分析价值；语义层的打磨需要"跑一版→读→改→重跑"的循环，脚本里是几分钟一轮，App 里是几小时一轮。

### 7.2 两层服务架构（核心，不可违反）

> **硬规则：凡是能确定性计算的，一律不许交给 LLM。LLM 只做"必须理解语义"的事。**

**A 层 · 机械统计与建模**（本地、零成本、可重现）
解析归一化 → 去重清洗 → 时序重建与分桶 → 基础指标 → 实体候选抽取（N-gram/TF-IDF/共现）→ 突变与周期检测 → FTS5 索引

**B 层 · 语义分析**（LLM、有成本、需缓存）
对话分类 → 实体抽取与消歧 → 实体类型判定 → 情绪原语+对象+强度 → 提问类型 → 意图抽取 → 周期摘要 → 五维打分与引据 → 问答

**两者关系（三条命脉）：**

1. **A 是 B 的省钱闸门** —— A 决定哪些对话值得送、送哪几段。不做这层，B 直接面对 227 万字。
2. **A 给 B 候选，B 给 A 答案** —— 机械版先产出实体候选词，LLM 只做消歧合并（比让 LLM 从零发现稳定得多）。
3. **A 是 B 的护栏** —— LLM 说"这周焦虑上升"，A 用事实表交叉验证；不一致则标记低置信度。**这是"凭什么信这个分数"的唯一机制。**
4. **B 回写 A** —— 情绪、实体类型、意图全部落进 SQLite 后，**所有视图都是纯本地查询，不再调 LLM**。LLM 只跑一次。

### 7.3 两遍不同温度（解决"稳定性 vs 被说中感"的冲突）

- **第一遍（低温，输出 JSON）**：逐条打标。负责稳定性与可比性。
- **第二遍（较高温，文本生成）**：基于第一遍结果写报告正文。负责"被说中感"，允许它敢下判断。

### 7.4 成本与工程简化

- DeepSeek 输入定价在**每百万 token 几元**量级（2026 年档，以官网为准）。全量 150–250 万 token ≈ **几元**；每周增量 2–3 万 token 可忽略。
- **因此：v1 不做增量、不做缓存、不做断点续跑优化。改完 prompt 直接全量重跑。** 仅做最简并发 + 重试。此项可省 1–2 天工程量。
- 全量打标约 917 次调用（按对话分批），并发下几十分钟跑完。

### 7.5 依赖

- Python 3.13 + SQLite（含 FTS5）
- DeepSeek API（用户自备 Key；UI 需支持切换厂商与模型）
- 报告渲染：本地 HTML + Chart.js（CDN 或本地化）
- 目标仓库：https://github.com/CG11037/deepseek-self

## 9. 给开发 Agent 的第一步指令

**Day 1 的任务只有一件事：把数据变成可查询的事实表，并输出第一张图。当天结束时必须能看到东西。**

具体步骤：

1. 读取项目内 `data/conversations.json`（34.4 MB，已就位），按 §3.2 的结构解析。**使用相对路径，不要写死盘符。**
2. **按 `message.id` 去重**；只保留 `REQUEST`（用户）与 `RESPONSE`（AI）两类 fragment，剔除 THINK/TOOL_*。
3. 建 SQLite 表：`conversations`、`messages`、`entities`（先留空）、`period_facts`。启用 FTS5。
4. 计算并落库（纯 Python，不调任何 API）：
   - 每周/每月消息量、用户字数、对话数
   - 断档检测（哪些周/月为 0）
   - 活跃时段分布（按小时）
   - 每轮对话的用户消息数分布
5. 输出一个 HTML 文件，画两张图：月度消息量柱状图（空档月份显式标注为"无记录"）、活跃时段分布图。

**约束：Day 1 不许调用任何 LLM API，不许写 prompt，不许搭前端框架。** 这一天的产出是事实，不是分析。

**验收**：脚本可重复运行，结果稳定；HTML 打开即可看到 20 个月的真实分布（应能看到 2026-03/04/09 三个高峰，以及 2025-07/09/10、2026-02 的空档）。

- ~~成本高一个数量级，必须做增量~~ → 实测成本仅几元，全量重跑更划算
- ~~"长期只能作为背景"~~ → 用户纠正：行为/认知层有全量数据，长期分析照做；仅情绪层历史稀疏需标注
- ~~只做变化驱动就够~~ → 变化驱动看不见平坦的部分；"自我"恰是不变的东西，必须配"从未改变的事"视图
