## 3. 硬约束（违反即返工）

### 3.1 数据处理

1. **必须按 `message.id` 去重。** `mapping` 是带分支的树（重新生成会产生分支），同一条用户消息会重复出现。实测中同一段"高中回忆"重复了 4 次。不去重会导致所有分值和引据被重复内容带偏。
2. **只保留 `REQUEST`（用户）和 `RESPONSE`（AI）两类 fragment。** 剔除 `THINK` / `TOOL_OPEN` / `TOOL_SEARCH` / `TOOL_FIND` / `SEARCH` / `FILE`——这些是模型内部过程，不含用户信息，占全部片段约 72%。
3. **红线内容局部打码，不整条剔除。** 代码、密钥、内网地址、财务数据替换为 `[REDACTED]`，消息本身继续参与分析。

### 3.2 架构

4. **A 层 / B 层分离（需求文档 §7.2）。硬规则：凡是能确定性计算的，一律不许交给 LLM。LLM 只做"必须理解语义"的事。**
   - A 层（机械统计与建模，本地零成本）：解析去重、时序分桶、基础指标、实体候选（N-gram/TF-IDF/共现）、突变检测、FTS5 索引
   - B 层（语义分析，LLM）：对话分类、实体消歧与类型判定、情绪原语+触发对象+强度、提问类型、意图抽取、周期摘要、五维打分与引据、问答
5. **B 层结果必须回写 SQLite。** 回写后所有视图为纯本地查询，不再调用 LLM。
6. **两遍不同温度**：
   - 第一遍低温，输出结构化 JSON（负责稳定性与可比性）
   - 第二遍较高温，基于第一遍结果生成报告正文（负责"被说中感"，允许敢下判断）
7. **v1 不做增量、不做缓存、不做断点续跑优化。**改完 prompt 直接全量重跑（成本仅几元）。只做最简并发 + 失败重试。
8. **信号筛选是必做项。** 917 条对话中仅 15.5% 含内在信号。不筛选就把全量喂给模型打分，测出的会是"这周学 Hadoop 学得很猛"，而不是焦虑水平。

### 3.3 输出质量

9. **每个五维分值必须配引据**（1–2 条真实对话原句或摘要，可点击跳原文）。无引据的分值不展示。
10. **情绪必须绑定触发对象。** "焦虑 7 分"不允许出现；必须是"焦虑（面试准备）7 分"。
11. **数据稀疏时显式标注"信号不足"，禁止插值、禁止编造曲线。**
12. **空档必须显式标注为"无记录"，禁止用前后值连成平滑线。** "你消失了三个月"本身就是要看见的事实。
13. **A 层与 B 层结论冲突时，以 A 层为准**，给 B 层结论打"存疑"标记并附事实对照。

## 4. 数据源事实（已实测，不要重新猜测，用它做自检锚点）

### 结构

```
顶层：list
conversation: { id, title, inserted_at, updated_at, mapping }
mapping:      { <node_id>: { id, parent, children[], message } }
message:      { model, inserted_at, fragments[] }
fragment:     { type, content }
```

### 实测数字

| 项 | 数值 |
|---|---|
| 对话数 | 917 |

| 模型分布 | deepseek-reasoner 8,790 / deepseek-chat 893 |

## 6. 分阶段执行

每个阶段结束**必须停下并输出自检报告**（见 §8），通过后才进入下一阶段。

### Phase 1 — 地基（不调用任何 LLM）

- 解析 `conversations.json`，去重，剔除过程数据，红线打码
- 建表：`conversations` / `messages` / `entities` / `period_facts` / `annotations`（B 层回写用）
- 计算并落库：每周与每月的消息量、用户字数、对话数；断档检测；按小时活跃分布；对话轮次分布
- 输出 HTML：月度消息量柱状图（空档显式标注"无记录"）+ 活跃时段分布图

**禁止：本阶段不得调用任何 LLM API，不得写 prompt。**

### Phase 2 — 语义层

- **信号筛选**：先判定对话是否含内在状态（情绪/困惑/自我反思/价值判断），只对筛出的部分做深度打标
- **实体候选**：A 层用 N-gram/TF-IDF 产出候选词，B 层只做消歧与类型判定（兴趣/项目/任务/人物/自我信念）
- **打标**：一次调用输出结构化 JSON，字段不少于：`emotion_primitives[]`（含 `label` / `object` / `intensity` / `quote_id`）、`question_type`、`entities[]`、`intent`、`self_relevance`、`confidence`
- **情绪词表**：首版用预设中文词表（焦虑/迷茫/挫败/疲惫/兴奋/好奇/掌控感 等），**预留个人词表切换接口**，不实现自动归纳
- **周期汇总**：五维分值 + 引据；事件检测（开始/结束/峰值/空档，"结束"须区分"完成"与"放弃"）
- 全部回写 SQLite

### Phase 3 — 报告（Phase 2 完成后立刻做，优先于后续所有功能）

- 生成周期报告 HTML：**首屏是本周关键事件时间线**，其次五维雷达（引据可点击跳原文），再次行为层统计
- **两种语气模式**：复盘模式（冷静、结构化、给行动建议、数据密度高）/ 陪伴模式（温和、少数据、不下判断、不给建议）。同一份数据两套措辞
- 输出三层：描述 → 归因 → 行动

**此阶段产出第一份可读报告后，立刻停下交付用户阅读。** 用户的反馈优先于后续所有开发。

### Phase 4 — 实体与长期视图

- 实体表填充与生命周期曲线；"完成 vs 放弃"判定
- "从未改变的事"视图
- 20 个月行为/认知层长期曲线（关注领域迁移、提问方式演变、活跃时段变化、对话深度演变）
- 情绪层历史周期显式标注"信号不足"

### Phase 5 — 问答与收尾

- RAG 问答：按实体/时间检索 → 组装上下文 → 生成。"我在焦虑什么"这类问题必须能答且带引据
- 导出 Markdown / PDF
- 身份画像卡（推断 + 强制首次确认 + 可编辑）

## 附：本项目的一句话立场

厂商做的是"**对用户建模**"——目的是预测你、迎合你、让你留下来。
我们做的是"**给用户一面镜子**"——目的是让你看见自己，然后你爱去哪儿去哪儿。

技术几乎一样，动机完全相反。因此：
**永远不要跟服务端比"谁的分析更漂亮"。** 只做服务端不会做的四件事：认知层（从提问行为反推思考方式）、跨周期追踪、跨平台统一、可验证引据。
